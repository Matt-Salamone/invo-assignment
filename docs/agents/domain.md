# Domain Docs

## Read before exploring

Read the root `GLOSSARY.md` when present. If a `GLOSSARY-MAP.md` exists instead, follow its pointers to relevant glossaries. Read ADRs in `docs/adr/` that affect the area being explored.

If these files do not exist, proceed without treating their absence as a setup error. Domain-modeling creates them when terms and decisions are established.

## Layout

Use a single context: one root glossary and root `docs/adr/` directory. A multi-context layout is unnecessary for the initial skill project.

## Vocabulary and decisions

Use defined glossary terms consistently in specifications, tickets, code, and diagrams. Surface a conflict with an existing ADR explicitly before treating a different decision as settled.
