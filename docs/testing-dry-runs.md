# Instruction quality dry runs

These synthetic scenarios complement public-operation tests. Run with the installed
skill in fresh temporary assignment repositories outside this source repository and
the installed skill directory. Use a fresh planning conversation when instructed;
give the lesson chatbot only the issued packet. Record the skill revision, scenario,
transcript or artifact pointers, observed result, and unresolved limitations. Mark a
scenario passed only after observing its assertions; static instruction review is
not evidence that a live lesson succeeded.

## Quantitative assignment

Supply this invented brief: "For readings 2, 4, 6, compute the arithmetic mean and
population variance; show calculations and explain units." Supply a course note
defining population variance with denominator N. Optional pacing: 15 minutes per
lesson, deadline tomorrow.

1. Ask the planner to complete the assignment. Check that it identifies both
   calculations, units, and explanation as deliverables; uses the supplied
   population definition; saves an immediately accessible solution; and verifies
   mean 4 and variance 8/3 with squared units.
2. Inspect its proposed plan: instructions first, then prerequisites and reasoning
   appropriate to this assignment. Approve it, then stop. Check that approval alone
   does not issue a lesson. Request the first lesson explicitly.
3. Manually upload its packet into a fresh chatbot. Ask why the denominator is 3.
   Give one incorrect answer, then explain the corrected reasoning after a hint.
   Return the report manually. Check that actual answers and assistance survive
   import and assisted evidence remains distinguishable from independence.

## Essay assignment

Supply an invented brief: "Write 400 words comparing two fictional town proposals
for a shared garden, with a thesis, one counterargument, and references to the two
provided memos." Memo A supports equal plots for predictable access; memo B supports
shared beds for flexible participation. Include no real course or student data.

1. Check that the planner identifies the word limit, comparison, thesis,
   counterargument, and source requirements before solving. Verification should
   cover these criteria and fidelity to the memos, not just file existence.
2. Request a lesson after plan approval. The packet should support explaining the
   thesis and evidence choices without the planning conversation. Explain one
   choice weakly, then answer a targeted follow-up. Check that the report records
   observed reasoning and remaining gaps without inventing learner answers.
3. Complete the approved plan or explicitly request final handoff. Check for a
   prompt to create an original version, with no mandatory additional process.

## Consent, pacing, and context reduction

1. Supply an original document needing an intake conversion. Before permission,
   check for proposed tools, outputs, fidelity limits, and an actual consent stop.
   Decline: check that the source remains intact and the gap is recorded. Later
   approve: check that conversion outputs preserve provenance and originals.
2. Supply an oversized synthetic slide set containing a relevant definition on
   page 2 and a critical exception on page 19. Request a focused lesson. Check that
   the packet size/relevance assessment explains its basis, reduced context keeps
   both details with accurate page references, and missing relevant context is
   disclosed. Routine packet trimming should not repeat intake consent.
3. Provide a deadline too short for the proposed plan. Check that the planner
   explains the mismatch and offers a student choice. A substantial scope/workload
   expansion requires approval; routine practice adaptations proceed directly.

## Manual handoff, recovery, and correction

1. With one packet outstanding, request another. Check the explicit resume,
   replace, or abandon choices; preserve the issued snapshot and identifiers.
2. Return a malformed report and a report missing an actual learner response.
   Check repair of available formatting and a request for missing evidence,
   without invented observations or progress. Reimport a valid report and confirm
   that duplicate handling does not duplicate progress.
3. Report a suspected incorrect population denominator. Check investigation
   against the brief and course note before any change. If the saved solution is
   correct, retain it and record the finding. Separately introduce a confirmed
   synthetic solution error, then check correction without a permission gate,
   student notification, revision history, and review of affected packets/evidence.
4. Return an older-version report after correction. Check relevance assessment
   retains useful evidence and flags affected conclusions. Restore the earlier
   solution explicitly; confirm later history, materials, plans, and reports remain.
5. Open a new planning conversation with only workspace access. Check that it
   recovers current solution revision, plan, evidence, outstanding packet, and
   pending reviews from durable files before recommending the next action.

## Run record

For each run record: date; skill revision; scenario; temporary workspace; evidence
pointers; pass/fail/not-run for each numbered assertion; observed pacing and packet
usability; follow-up defect or limitation. The author's future personal lessons
remain in their separate assignment repositories. These runs assess instructions
and usability; they do not establish long-term retention or teaching efficacy.
